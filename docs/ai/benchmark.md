# Benchmark — מטריצת השראה

מקורות לימוד דפוסים בלבד. **אין להעתיק** UI, קוד או assets. הפניה בכל שורה: "מה ללמוד" / "מה מתאים" / "מה לא מתאים" / "אסור להעתיק" / "עדיפות ליישום".

---

## Hevy — דיווח סטים מהיר

- **ללמוד:** דיווח סט בטאפ אחד, ערכי סט קודם כ־placeholder, superset UX, טיימר מנוחה מובנה, שיאים אישיים מסומנים inline.
- **מתאים לנו:** דיווח מהיר, previous set indicator, super-set grouping, PR flags בזמן דיווח.
- **לא מתאים:** feed חברתי, workout sharing, follower system.
- **אסור להעתיק:** לוגו/גופן/סכימת צבעים, אנימציות חגיגה, כפתורי share.
- **עדיפות:** 🔴 גבוהה — היסוד ל־UX של תחום חדר כושר ובית.

## Strong — מינימליזם ודיוק

- **ללמוד:** ריק חזותי בהיר, טיפוגרפיה גדולה קריאה, גרפי היסטוריה נקיים, ייצוא CSV.
- **מתאים לנו:** מינימליזם, קריאות במובייל, גרפים פר־תרגיל, export לכל דאטה.
- **לא מתאים:** עסקאות/subscription flow, ניוזלטרים.
- **אסור להעתיק:** ויזואל, אייקונים, סכימת עמודות.
- **עדיפות:** 🟠 בינונית — נכנס עם מסכי ניתוח.

## Fitbod — התאמה חכמה לציוד

- **ללמוד:** בחירת ציוד זמין → פילטור תרגילים אפשריים; המלצות החלפה כשציוד תפוס; היסטוריית תרגיל תמידית זמינה בקליק.
- **מתאים לנו:** בחירת location (בית/חדר) → סינון exercises; "החלף תרגיל" עם alternatives; היסטוריה מהירה per exercise.
- **לא מתאים:** תוכניות אוטומטיות של המערכת, אלגוריתם "מה לאמן היום" (סותר את "המשתמש קובע מטרות").
- **אסור להעתיק:** אלגוריתם ההמלצות שלהם, מודל התשלום.
- **עדיפות:** 🟡 בינונית־נמוכה — אחרי שלד strength עומד.

## Everfit — סוגי סטים ותבניות גמישות

- **ללמוד:** סוגי סטים עשירים (drop, cluster, AMRAP, EMOM, time-under-tension), RPE + RIR, template blocks (חימום/עיקרי/finisher).
- **מתאים לנו:** תמיכה ב־set types מגוונים; RPE ו־RIR בשדות מובנים; חלוקת template ל־blocks.
- **לא מתאים:** platform מאמן↔מתאמן, chat, assignments — סותר single-user.
- **אסור להעתיק:** UI ה־coach dashboard, כל flow שיתופי.
- **עדיפות:** 🟠 בינונית — נכנס עם עומק תבניות.

## TrainHeroic — ספריות, PRs, תכנון עומס

- **ללמוד:** מבנה program → block → week → session; ספריית תרגילים עשירה עם עומס מצטבר; PR tracking אוטומטי.
- **מתאים לנו:** ארגון היררכי של תוכניות (אולי בעתיד); PR detection derived; חישובי volume/tonnage שבועיים.
- **לא מתאים:** marketplace של תוכניות, מודל B2B.
- **אסור להעתיק:** תוכן תוכניות של מאמנים ספציפיים.
- **עדיפות:** 🟢 עתידית — אחרי שיש 3+ חודשי דאטה אמיתי.

## Suunto — נתוני ריצה ומקורות מדידה

- **ללמוד:** הפרדת מדידות לפי מקור (GPS vs footpod vs treadmill calibration); השוואת מסלולים; פרופיל pace/HR/altitude.
- **מתאים לנו:** `suunto_readings` נפרד מ־`run_segments` (ADR-0009); כיול per-treadmill (`treadmills` table); סימון מקור בכל קריאה.
- **לא מתאים:** ecosystem watch ↔ phone ↔ cloud מלא — יבוא קבצים ידני מספיק לשלב זה.
- **אסור להעתיק:** UI השעון, מפות של Suunto.
- **עדיפות:** 🟠 בינונית — נכנס עם תחום ריצה.

## סיכום עדיפויות רוחביות

1. **Hevy set-logging pattern** — היסוד ל־strength.
2. **Suunto raw/derived separation** — היסוד ל־running.
3. **Everfit set types + RPE/RIR** — עומק דיווח.
4. **Fitbod equipment filtering** — נוחות בחירת תרגיל.
5. **Strong minimalism** — קו מנחה ויזואלי.
6. **TrainHeroic hierarchy** — מבנה תוכניות (עתידי).
